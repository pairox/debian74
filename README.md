# PHP 7.4 base image

Публичный базовый образ для legacy-приложений на PHP 7.4. Он содержит PHP-расширения, системные зависимости, Supervisor и Composer, используемые в `v_api`.

Образ собирается GitHub Actions и публикуется в GitHub Container Registry:

```dockerfile
FROM ghcr.io/pairox/debian74:7.4

COPY ./api /var/www
WORKDIR /var/www
RUN composer install --no-interaction --prefer-dist --optimize-autoloader
```

В Dockerfile приложения больше не нужны `apt-get`, PECL и `docker-php-ext-install`: они выполняются единожды при публикации этого образа. Конфигурация Supervisor остаётся в приложении.

## Публикация

Запушьте изменения в ветку `main` или запустите workflow **Publish PHP 7.4 base image** вручную. После первого запуска откройте пакет `debian74` в GitHub и убедитесь, что его visibility установлена в **Public**.

Теги:

- `7.4` — актуальный базовый образ PHP 7.4;
- `7.4.33` — тот же образ с фиксированной версией PHP;
- `sha-…` — образ конкретного коммита;
- `v*` — тег релиза репозитория.

Для воспроизводимой сборки APT использует Debian snapshot `20240801T000000Z`. Это исключает 404, возникающие из-за удаления старых пакетов Bullseye с обычных зеркал.

## Исправления безопасности PHP 7.4

PHP остаётся **7.4.33**. При сборке CLI и FPM пересобираются из исходников
официального образа с [минимальным бэкпортом команды PHP](https://github.com/php/php-src/commit/712e60f9edfd03f0960fc4fc3c2c375f42b90aa2)
для **CVE-2026-109618 и CVE-2026-109619**. Патч хранится в репозитории,
зафиксирован по SHA-256 и применяется до сборки расширений. Это точечное
исправление двух CVE, а не возобновление полной поддержки PHP 7.4.

Особенности upstream-бэкпорта: Session Upload Progress отключён на уровне кода;
при нехватке памяти worker немедленно завершается без PHP shutdown callbacks.
Обычные загрузки файлов сохраняются, но приложения с нативным индикатором
прогресса и обработчиками ошибок OOM нужно проверить отдельно.

Workflow сначала собирает образ и проверяет PHP/FPM, расширения и поведение OOM,
затем публикует проверенный образ. Проверки также выполняются внутри Dockerfile.
Проверить уже собранный образ можно командой:

```sh
docker run --rm --entrypoint sh ghcr.io/pairox/debian74:7.4 /usr/local/bin/verify-php-security
```

После публикации нужно **пересобрать производные образы приложений со свежей базой**
(`docker build --pull ...`) и пересоздать контейнеры. Публикация базового образа
сама по себе не меняет работающие приложения. Теги `7.4` и `7.4.33` сохраняются;
для точного закрепления сборки используйте digest образа.

Debian snapshot по-прежнему фиксирует системные библиотеки на август 2024 года.
Исправление PHP не обновляет автоматически остальные зависимости образа.
