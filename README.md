# PHP 7.4 base image

Публичный базовый образ для legacy-приложений на PHP 7.4. Он содержит PHP-расширения, системные зависимости, Supervisor и Composer, используемые в `v_api`.

Образ собирается GitHub Actions и публикуется в GitHub Container Registry:

```dockerfile
FROM ghcr.io/pairox/debian74:7.4.33-20261120

COPY ./api /var/www
WORKDIR /var/www
RUN composer install --no-interaction --prefer-dist --optimize-autoloader
```

В Dockerfile приложения больше не нужны `apt-get`, PECL и `docker-php-ext-install`: они выполняются единожды при публикации этого образа. Конфигурация Supervisor остаётся в приложении.

## Публикация

Запушьте изменения в ветку `main` или запустите workflow **Publish PHP 7.4 base image** вручную. После первого запуска откройте пакет `debian74` в GitHub и убедитесь, что его visibility установлена в **Public**.

Теги:

- `7.4.33-20261120` — новая ревизия образа с security-патчами и Debian 12;
- `7.4` — актуальный базовый образ PHP 7.4;
- `7.4.33` — тот же образ с фиксированной версией PHP;
- `sha-…` — образ конкретного коммита;
- `v*` — тег релиза репозитория.

## Обновление безопасности от 20.11.2026 (Europe/Minsk)

PHP сохраняет версию **7.4.33**, CLI/FPM и расширения собираются из исходников.
Версия образа — **7.4.33-20261120**. Формат:
`<версия PHP>-<дата выпуска YYYYMMDD>` — без названия компании и номера ревизии.
Например, выпуск на следующий день — `7.4.33-20261121`.
Дата задаётся для выпуска и не меняется автоматически при запуске CI.
Текущий набор патчей взят из пакета Surý `7.4.33-37`;
номер пакета поставщика учитывается отдельно от версии образа.

Версионные теги следует сохранять за одним опубликованным артефактом:
при последующих изменениях выпускайте образ с новой датой.
Для нескольких сборок за одну дату различайте артефакты по digest или тегу `sha-…`.
Повторная сборка с live APT/Composer может дать другой состав даже при том же
коммите, поэтому для точной фиксации используйте digest. Теги `7.4` и `7.4.33`
служат обновляемыми указателями. `php -v` продолжает показывать upstream
`7.4.33`; версия дистрибутива образа указана в теге и метке
`io.pairox.image.version`.
Вместо одиночного октябрьского патча применяется набор из **149 патчей**
пакета Surý `1:7.4.33-37+debsuryorg12.1+php+1`, включая исправления,
перенесённые из security-релиза PHP 8.2.36 от 19 ноября 2026 года.
Источники, контрольные суммы, порядок, исключения и ограничения описаны
в [docker/patches/README.md](docker/patches/README.md).

Основа финального образа изменена с Debian 11 Bullseye и snapshot августа
2024 года на **Debian 12 Bookworm**. При каждой сборке используются действующие
APT-репозитории, выполняется обновление установленных пакетов. Старая PHP-база
служит только источником оригинального архива PHP, shell-помощников и настроек
FPM; её бинарники, расширения и библиотеки в финальный образ не копируются.
Параметры сборки и пути `/usr/local` сохранены; PCRE2 используется системный.
PHP собирается заново под OpenSSL 3 и библиотеки Bookworm.

Расширения обновлены: **imagick 3.7.0 → 3.8.1**, **memcached 3.2.0 → 3.4.0**.
Архив PHP, PECL-архивы и каждый патч проверяются по SHA-256. Системные пакеты,
базовый Debian, Composer 2 и сканер получают актуальные версии при сборке;
полная побитовая воспроизводимость не заявляется. Список фактических пакетов
попадает в `/usr/local/share/php-security/debian-packages.txt`.

Особенности октябрьского upstream-бэкпорта сохраняются: Session Upload Progress
отключён в коде и конфигурации; при OOM worker немедленно завершается без PHP
shutdown callbacks. Обычная загрузка файлов остаётся доступной. Нужны проверки
приложений, использующих индикатор прогресса, OOM callbacks, OpenSSL, ImageMagick,
PostgreSQL-клиент и поведение новых системных библиотек.

## Проверки CI и ограничения

В репозитории используется **GitHub Actions** (`.github/workflows/publish.yml`);
конфигурации GitLab CI нет. Workflow собирает образ, проверяет версию PHP,
расширения, OpenSSL, создание PNG через Imagick, конфигурацию FPM, запуск Composer
и безопасное завершение при OOM. Затем Trivy формирует полный JSON-отчёт
`image-security-report` и блокирует публикацию при HIGH/CRITICAL-находках,
для которых доступно исправление. Находки без исправлений остаются в отчёте;
они требуют отдельной оценки. Ошибка сканера также останавливает публикацию.

Сканер не подтверждает полноту backport-патчей самостоятельно собранного PHP.
PHP 7.4 снят с поддержки upstream; журнал поставщика содержит частичный
mysqlnd backport CVE-2025-1218. Поэтому нельзя обещать отсутствие всех уязвимостей.
Сам набор патчей, PHP-код приложений и зависимости Composer требуют дальнейшего
контроля. Миграция на поддерживаемый PHP остаётся отдельной задачей.

Локально проверены контрольные суммы и применение всех патчей к чистому PHP
7.4.33 с `--fuzz=0`, синтаксис shell/YAML и ShellCheck. **Сборка образа, runtime-
проверки, сканирование и запуск CI не выполнялись** — их выполняет workflow
после вашей отправки изменений.

Проверить собранный образ:

```sh
docker run --rm --entrypoint sh ghcr.io/pairox/debian74:7.4.33-20261120 /usr/local/bin/verify-php-security
```

После успешной публикации нужно **пересобрать производные образы приложений
со свежей базой** (`docker build --pull ...`), протестировать их и пересоздать
контейнеры. Обновление базового тега не меняет работающие приложения.
Новая сборка публикуется с тегом `7.4.33-20261120`; теги `7.4` и `7.4.33`
также обновляются как совместимые aliases. Закрепляйте проверенные образы по digest.

Откат: вернуть предыдущие версии файлов и предыдущий проверенный digest образов
приложений. Старые mutable-теги могут быть перезаписаны после публикации;
сохраните предыдущие digest до выкладки. Откат возвращает и прежние уязвимости.
